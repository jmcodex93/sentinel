# Sentinel Plugin - Development Rules

## Project Overview
Sentinel (v1.36.3) is a Cinema 4D quality control and workflow automation plugin designed for professional 3D production workflows. **Originally built as YS Guardian at Yambo Studio**, now maintained and extended by Javier Melgar as Sentinel — keeping the watchdog spirit while expanding into versioning, status tracking, and modern mograph workflow tools. It acts as a real-time watchdog that continuously monitors scenes for production issues, plus provides render management and scene tools.

The plugin performs **12 quality checks** in real-time:
1. **Lights Organization** - Ensures all lights are properly organized in a "lights" group (Select + Fix)
2. **Visibility Consistency** - Detects objects with mismatched viewport/render visibility (Select)
3. **Keyframe Sanity** - Warns about multi-axis keyframes that can cause animation issues (Select)
4. **Camera Shift Detection** - Alerts when cameras have non-zero shift values (Select + Fix)
5. **Render Preset Compliance** - Ensures only approved render presets exist (Info)
6. **Assets (Textures)** - Missing textures, absolute paths, RS Node material paths (Info)
7. **Unused Materials** - Detects materials not applied to any object (Select + Fix)
8. **Default Names** - Objects still using C4D default names like "Cube", "Null" (Select)
9. **Output Paths** - Missing tokens, empty paths in render settings (Info)
10. **Take Validation** - Camera assigned per take, output paths with $take token (Info)
11. **FPS / Frame Range** - Validates FPS, start frame = 1001 (VFX standard), frame step, timeline + preview alignment, all presets (Info + Fix)
12. **Cross-Aspect Safe Area** - Verifies opt-in marked subjects (UserData) stay inside per-format safe-area regions when delivering across multiple aspect ratios via Multi-Format Setup. Auto-refresh uses current frame; Info button runs full keyframe sweep (Select + Info)

Additional features: RS AOV management (Essentials/Production/Light Groups), Scene Collector, QC Report export, Render Presets with aspect ratio toggle, Texture Repathing tool (multi-renderer bulk find/replace + smart-fix), and a full suite of scene tools.

## Development Flow
- After changing package structure or classes registered with Cinema 4D, restart Cinema 4D. Do not rely on "Reload Python Plugins" for package reloads: live ObjectData/GeDialog instances can keep references to old module objects and create split-brain state.
- Install/copy the full plugin folder contents together: `sentinel_panel.pyp`, `sentinel/`, `res/`, `abc_retime/`, and support scripts. The `.pyp` alone is not a complete plugin anymore.

## Development Rules

### 1. FOCUS
- **ONE PROBLEM AT A TIME**: Don't try to solve everything at once
- **CORE FUNCTIONALITY FIRST**: Get the basic feature working before adding complexity
- **NO FEATURE CREEP**: Don't add features that weren't requested

### 2. FILE MANAGEMENT
- **EDIT, DON'T CREATE**: Modify existing files instead of creating new versions
- **NO HELPER SCRIPTS**: Don't create installation scripts, test scripts, or diagnostic tools unless specifically requested
- **KEEP IT SIMPLE**: The fewer files, the better

### 3. PROBLEM SOLVING
- **IDENTIFY ROOT CAUSE**: Understand WHY something isn't working before trying to fix it
- **TEST INCREMENTALLY**: Make small changes and test each one
- **DOCUMENT FINDINGS**: Keep notes about what works and what doesn't in this file

### 4. CODE PRINCIPLES
- **MINIMAL DEPENDENCIES**: Use only Cinema 4D's built-in Python libraries when possible
- **FALLBACK GRACEFULLY**: If a feature can't work, fail silently with a simple message
- **NO OVER-ENGINEERING**: Simple solutions are better than complex ones

### 5. GOAL-DRIVEN EXECUTION
Before coding, restate the task as a verifiable success criterion so the loop can close on its own instead of waiting for the user to eyeball it.
- **"Add QC check X"** → "Open a scene that violates X, run QC, confirm the new check reports it; open a clean scene, confirm it doesn't."
- **"Fix bug Y"** → "Reproduce Y in C4D first, then verify the fix makes the repro pass."
- **"Refactor Z"** → "All 12 QC checks still produce the same results before and after."
- **"Add UI button"** → "Plugin reloads without errors, button appears in expected section, click triggers the action, status text updates."

For multi-step work, write the plan as `step → verify` pairs. Weak criteria ("make it work") force ping-pong; strong criteria let the work finish in one pass.

## Data Persistence

### Saved Per Computer/User (Persistent via `sentinel_settings.json`; legacy `ys_guardian_settings.json` is auto-migrated on first run)
- **Artist Name**: Stored in Cinema 4D preferences folder
- **Compositor Target**: Nuke vs After Effects selection
- **Multi-Part EXR**: On/off preference
- **Snapshot Directory**: RS snapshot source path
- **Standard FPS**: Studio FPS standard for QC check #11 (default 25, key `standard_fps`). A project `sentinel_rules.json` `fps` overrides this and disables the machine control with a "defined by project ruleset" caption (v1.6.0)
- **Texture Repathing presets**: Last 5 Find/Replace pairs (key in `sentinel_settings.json`)
- **Panel Layout**: Window position and docking state (managed by Cinema 4D)

### Per Project (Shared, via `sentinel_rules.json`) — v1.6.0
- **Ruleset**: FPS, start frame, approved presets, default names, safe-area insets, `matwire_suffixes` (sufijos extra por canal para RS Material from Folder, aditivos — v1.32.1), per-check severity (FAIL/WARN), and per-check on/off. Discovered from the scene folder + up to 3 ancestors (nearest wins, no cross-file merge; shadowed files surfaced in the header + QC Report). Precedence: **project rules > machine settings > embedded defaults**. Per-key validation (one bad key is rejected by name, the rest applies). Resolution cached by (path, mtime), invalidated with the QC cache — edits/deletes take effect without restart. Absent file → current defaults. Publishable to a shared folder so a whole team validates against the same rules.

### Per Scene Base (Sidecar JSON next to the `.c4d`, shared across all `_v###` versions)
- **`<base>_history.json`**: Smart Save Version log (comment, QC score, scene stats). As of v1.6.0 each entry is schema v2 `{passed, total, new, accepted}`; older entries render as "X/12 (legacy)"
- **`<base>_notes.json`**: Free-form scene notes + TODO checklist (v1.5.1)
- **`<base>_baseline.json`** (v1.6.0): Accepted QC violations with author + reason, schema v1. Identity = `check_id` + hierarchical path + sibling index — **the LOCATION** (parametric checks snapshot the rule value). The object GUID is deliberately NOT part of it: C4D regenerates it on every document load (measured v1.34.1), so including it made every acceptance expire the moment the artist reopened the scene. Merge-on-write (atomic tmp+rename), Synology conflicted-copy detection + merge on load, read-only lockout on an unreadable sidecar. Scene Collector copies + renames it (plus the effective `sentinel_rules.json`) into the delivery
- **Note**: sidecars are copied to the delivery folder by Scene Collector and renamed to the clean delivery base

### Fetched From Scene (Per Document)
- **Shot ID**: Read from Main Take name, synchronized with scene
- **Render Preset**: Read from active render data, matches scene settings

### Runtime Only (Per Session)
- **QC check results**: Cached with 0.5s cooldown, dirty-flag invalidation via CoreMessage
- **Scene stats**: Object count, polygon count, materials, lights

## Current Status (v1.36.3)

### What Works ✅
- **Reset All deja de comerse trabajo: deshacible + el confirm dice QUÉ se pierde** (v1.36.3, rama `fix/reset-all-undo`, **pendiente de merge/live**): *Reset All* (sección Render) sustituía los presets de render de la escena por los 4 del template **borrando todos los existentes sin registrar un solo `AddUndo`** — era **la única operación irreversible del plugin**, viva desde la v1.0 en un proyecto donde "un solo Cmd+Z lo revierte todo" es contrato desde hace tres releases. Reproducido en vivo antes de tocar código: `['test_denoise', 'CLIENTE_9x16_final']` → reset → Cmd+Z → los presets del cliente **no vuelven**. **La receta de undo para `RenderData` no estaba medida en este proyecto, así que se midió** (sonda propia, C4D 2026.303, documento throwaway + `KillDocument` en `finally`, undo por `CallCommand(12105)`), y las tres variantes discriminan: **sin ningún `AddUndo`** (el código de hoy) el undo no devuelve nada — el caso base que prueba que la sonda mide algo; **sólo `UNDOTYPE_DELETE` antes de cada `Remove()`** devuelve los del artista pero **deja también los 4 del template** (7 presets, el fallo "funciona con uno, se rompe con N" en su forma de mitad-de-receta); **`UNDOTYPE_DELETE` antes de cada borrado + `UNDOTYPE_NEW` tras cada inserción**, todo en **un solo** `StartUndo`/`EndUndo`, restaura el estado exacto de partida — incluido **qué render data estaba activo**, que ningún `AddUndo` registra explícitamente y por eso no se da por hecho en ningún test. El bracket se abre **después** de clonar del template, así que cada retorno temprano por error sigue sin dejar paso de deshacer (un bracket vacío no materializa uno, medido en el spike de la v1.36), y un `finally` garantiza el `EndUndo` si algo revienta a mitad. La ruta nativa (`_force_render_settings`, con su `QuestionDialog`/`MessageDialog`) no cambia: el núcleo es el que gana el undo. **Pieza 2 — el confirm deja de pedir fe**: era una constante fija ("This replaces existing presets with standard settings") que se confirmaba a ciegas; ahora **nombra los presets que van a desaparecer**, leídos de la escena **en el momento de pedir el confirm** (`This deletes 2 presets that are not in the standard set: CLIENTE_9x16_final, test_denoise. Cmd+Z restores them.`), con cap de 5 nombres + `and N more` y singular propio. El criterio de "estándar" es **el mismo de QC #5** — `approved_presets` del ruleset a través de `normalize_preset_name`, ni re-derivado ni con los cuatro nombres del template a mano — así que un ruleset de proyecto que apruebe `CLIENTE_9x16_final` hace que **deje de contarse como pérdida** (con su test). Cuando no hay nada que perder **no se inventa alarma**: el aviso se lee distinto ("No custom presets in this scene…"). Si la lectura de escena fallara, el confirm degrada a la constante genérica **con línea de log** — un prompt de confirmación no puede ser lo que rompe la operación, pero tampoco puede callarse. El texto del panel va en inglés como el resto de esa superficie; el diálogo nativo conserva el suyo. **El arnés era otra vez el sospechoso** (décima recurrencia): el fake no modelaba `RenderData` ni **replay** de undos, así que un test de regresión habría comprobado "se llamó a `AddUndo`", no "el preset vuelve" — se añadió un doble con **pila de undo reproducible** (DELETE re-inserta en su hueco, NEW saca) que declara en su docstring lo que **no** modela (el puntero de activo, el coalescing). Alcance mínimo deliberado: el desplegable de presets y Force 9:16 **no se tocan**. 11 mutaciones, cada una tumbada por su test nombrado. pytest 1443 (+10), vitest 216.

- **El Pin captura también por descripción, y el informe deja de mentir** (v1.36.2, rama `fix/pin-description-capture`, **pendiente de merge/live**): bug de producción encontrado por el artista USANDO la herramienta — restaurar un pin sobre un setup de luces devolvía las **posiciones** y no las **intensidades**, y la fila cantaba `3 restaurados`. **No era un fallo de escritura sino de CAPTURA**: `_store_pin` guardaba los parámetros con `child_obj.GetData()`, y la **luz nativa de C4D guarda los suyos FUERA del `BaseContainer`** — `LIGHT_BRIGHTNESS` (90001), `LIGHT_COLOR` (90000) y `LIGHT_TYPE` (90002) sólo son accesibles por `GetParameter`/`SetParameter`; el pin nunca llegó a guardarlos. **Alcance medido antes de tocar código** (auditoría con oráculo funcional — capturar → perturbar → `SetData` → comparar — sobre parámetros de **primer nivel**, excluyendo la transformación): el problema está **casi confinado a la luz nativa** (112 probados, **87 se pierden**), mientras RS Light (107/107), cámara nativa (95/95), RS Camera (135/136, sólo *Shutter Offset*), RS Environment/Sun&Sky/Proxy (95/95), Octane Scatter/Decal (23/23) y siete generadores/deformadores (99/99) restauran enteros por el contenedor — los objetos de terceros usan el contenedor estándar y funcionan. **Límite declarado de esa auditoría: los `DescID` anidados NO están medidos**, así que el barrido es de primer nivel y nada más. **Pieza 1 — el contenedor sigue siendo el camino principal**, barato y suficiente para casi todo; la descripción es sólo el **complemento**, y se barre **únicamente lo que el contenedor no trae** (`_container_ids`), que es lo que mantiene el coste en cero para los objetos que ya restauraban al 100% — el barrido corre por cada objeto cubierto en cada captura, y un pin sobre un rig grande no puede volverse lento. Fuera del barrido por política: botones, separadores, grupos, texto estático, **enlaces** (`DTYPE_BASELISTLINK` — reescribir un enlace desde un pin re-cablearía la escena, no la restauraría), nombres de fichero y sub-contenedores; y **la transformación entera (ids 903-927), que ya restaura `SetMl`** — escribirla por dos caminos distintos es pedir una discrepancia. Un parámetro que el objeto vivo rechaza **no puede reventar la restauración**: cada escritura va en su propio `try` y sólo suma al conteo. **El esquema del payload NO sube** (sigue en `PIN_SCHEMA` 1) a propósito: los datos nuevos son aditivos y un pin de una build anterior se lee como "ningún parámetro extra" y se aplica igual — subirlo habría invalidado **todos** los pins ya guardados del artista para añadir algo que sólo complementa (mismo patrón con el que la Tarea 6 añadió las pistas). **Pieza 2 — el informe deja de mentir**: `_restore_report_text` contaba **objetos emparejados**, no parámetros devueltos, y que la captura cubra ahora el caso de la luz no cierra el agujero. Se **cuenta lo que no se pudo aplicar** y se dice en la fila, en dos sitios distintos porque son dos cosas distintas: lo que no se pudo **capturar** va en la línea de aviso (`⚠ N parámetros sin capturar`, visible **antes** de confiar en el pin) y lo que el objeto vivo **rechazó** al restaurar va en el informe (`3 restaurados · 1 parámetro sin restaurar`). **Descartada la verificación por lectura de vuelta** (escribir y releer cada valor para comprobarlo): duplicaría el coste de cada restauración y, con floats, vectores y tipos custom, produciría falsos "no restaurado" por redondeo — un aviso que se equivoca a menudo se acaba ignorando, que es exactamente el fallo que este arreglo existe para no repetir. **El arnés era, otra vez, el sospechoso**: los dobles de objeto de los dos suites de pin modelan el contenedor y **nada más**, así que "parámetro que existe en la descripción pero no en el contenedor" **no era un estado representable** y el test de regresión no habría probado nada (novena recurrencia del patrón). Doble nuevo `FakeDescribedObject` con las **dos superficies separadas** — `_data` (contenedor) y `_desc` (sólo descripción) — que es literalmente la diferencia medida entre una luz nativa y un RS Light. **Lo que el arnés sigue sin poder afirmar, y por eso es verificación en vivo**: qué expone realmente la descripción de una luz de C4D 2026, qué devuelve `SetParameter` cuando el objeto rechaza un valor (aquí se modela `False`, que es lo que documenta la API), y si la lista de `DTYPE_*` excluidos deja fuera algo que el artista sí querría de vuelta. **Juicio anotado, no medido**: un parámetro que se lee como `None` no se captura **y no se cuenta** — C4D dice que ahí no hay dato, y contarlo pondría un aviso permanente en la fila de todos los pins. **Fuera de alcance, con motivo**: el `Display Color`/`X-Ray` que la auditoría vio sin restaurar en todos los objetos cae dentro del rango de transformación que el brief manda excluir (903-927), así que no se persigue. pytest 1430 (+9).

### What Works ✅
- **Pulido de usabilidad — color automático del Pin + botón en Tools** (v1.36.1, rama `feat/v1361-polish`, **pendiente de merge/live**): dos piezas cortas salidas de ver al artista usar la escena de ejemplo. **(1) El icono del Pin se pinta solo, y sólo al nacer.** Con varios pins sobre un objeto todos eran el mismo icono gris en el Object Manager: no se distinguía un estado que guardó el artista de la red de seguridad `↩ Antes de restaurar` que la herramienta crea sola. Sentinel escribe ahora el tinte **NATIVO** del tag (`ID_BASELIST_ICON_COLORIZE_MODE` + `ID_BASELIST_ICON_COLOR`, los mismos dos parámetros que la fila "Color" ya expone) — **nunca una paleta propia ni `MSG_GETCUSTOMICON`**, que no llega a un `TagData` (medido y retirado en v1.35). Un pin normal nace con el **acento del sistema** (`colors.primary` `#5e6ad2`) y la red de seguridad con **`colors.muted`** (`#6b6f76`): el acento es el único cromatismo no-semántico que `DESIGN.md` permite (los colores de estado son exclusivos de fail/warn/pass, y esto no es un estado), y el gris apagado ES el mensaje — "esto lo hizo la herramienta, no tú". Difieren en tono **y** en saturación, así que la distinción sobrevive a no distinguir bien los colores. **Se escribe una sola vez, al CREAR el tag** (`Init` para un pin normal, la rama de creación de `_capture_safety_pin` para la red) y **jamás después**: ni al re-pinear, ni al restaurar, ni al sobrescribir la red de seguridad en cada restauración — son parámetros nativos y el artista manda sobre ellos. `Init` **no** pinta en `isCloneInit`: el clon va a recibir los datos del original, color incluido, y escribir ahí pisaría un color elegido a mano. Cinco de las mutaciones de esta pieza son precisamente "escribe el color en un sitio de más" (en `_store_pin`, en la rama de sobrescritura, en el clon) y cada una tumba su test. **(2) "Pin State" en Tools.** Hasta ahora un pin sólo se añadía por el menú nativo de tags de C4D — funciona y no lo descubre nadie, mientras Variants sí tenía botón. Op nueva `panel/tools/pin_state` (patrón exacto de `variant_set`: sin diálogos con su test `_forbid_dialog`, respuesta plana y JSON-serializable — nunca un `BaseTag`, y el cliente indexa el copy por `error`, no por `reason`) que pone un Sentinel Pin a cada objeto de la selección y **lo guarda ya** (un pin vacío no le sirve de nada al artista), con **un solo paso de deshacer para todo el lote**. Usa `GETACTIVEOBJECTFLAGS_0` (la selección cruda) y **no** el flag `_CHILDREN` de las herramientas de contención: un pin ya cubre el subárbol entero del objeto donde se sienta, así que arrastrar descendientes pondría un segundo pin redundante en cada hijo. Los fallos parciales se cuentan y se dicen (`Pinned 2 objects · 1 failed.`); si no aterrizó ninguno es un fallo, no un "0 pineados" que el toast pintaría de verde. **Grupo nuevo en Tools, con motivo**: un pin ni coloca, ni limpia, ni anima — ninguno de los tres grupos existentes nombra lo que hace, así que va a **"Return Points"**, el término que este proyecto ya usa para el arco v1.30→v1.36 (Pin = estados a los que volver, Variants = opciones a las que volver). `Variant Set` se queda donde está: moverlo es otra decisión, no la de esta tarea. Sin cambios en el motor de Pin ni en el de Variants. pytest 1421, vitest 216.

### What Works ✅
- **Sentinel Variants — opciones de escena a las que volver, de verdad** (v1.36.0, rama `feat/sentinel-variants`, **pendiente de merge**): la v1.36 iba a ser la "capa automática" (snapshot antes de cada operación destructiva) y **se descartó en el brainstorm**: al preguntar cuándo le había faltado ese punto de retorno al artista, la respuesta fue "nunca, es prevención". La sustituye lo que el artista **sí** hace cada semana — duplicar una rama y aparcarla en un null `backup` para probar dos modelados, dos animaciones o dos lightings. **Un tag Sentinel Variants = un CONJUNTO de opciones**, puesto sobre un null de **anclaje** que ocupa el sitio del original: el anclaje tiene exactamente **un** hijo (la opción montada) y las demás viven fuera de la jerarquía, en un contenedor de aparcado en la raíz con la visibilidad de editor y render apagadas. Seis gestos, cada uno **un solo paso de deshacer**: crear el conjunto sobre la selección, cambiar de opción (clic en su fila), duplicar la montada, renombrar, borrar, y **renderizar todas las opciones** sin montar ninguna a mano. Tag id `2099079`. **Por qué se SACA de la jerarquía en vez de ocultar o desactivar — medido, no supuesto** (`docs/research/2026-08-05-variant-isolation-spike.md`, C4D 2026.303, oráculo *Current State to Object* contando polígonos, es decir lo que el generador construye de verdad y no lo que dicen sus parámetros): un Cloner con dos hijos da **2584 polys con la rama oculta y 2584 sin ocultarla** — **ocultar NO aísla**, el generador sigue consumiendo la rama invisible (un Subdivision Surface igual: 96 → 96) — y **desactivar tampoco equivale a sacar** (**24 vs 54**: el Cloner sigue contando al hijo desactivado como un hueco en su reparto). Como la promesa del sistema es equivalencia exacta con "esta opción no existe", sólo sacarla la cumple: **el método manual del artista era el correcto desde el principio**. Límite honesto del propio spike: **el caso del deformador no está medido** (en los tres montajes el Bend no llegó a deformar el cubo, 0 puntos movidos de 218 — test nulo, no se cuenta como evidencia). ### Known Limitations ❌
- **Forcing Redshift Snapshot Directory**: Can't override Redshift's save location at runtime
- **Programmatic Snapshot Triggering**: No API access to trigger snapshots from code
- **Redshift must be configured manually**: RenderView → Preferences → Snapshots → EXR format. **Verified unfixable (2026-07-10)**: the "Save snapshots as EXR" checkbox is session-only Qt state (widget `snapshotsAsEXRCBox`). RenderView persists state to `prefs/redshift_rv.cfg`, but that file has NO key for the EXR toggle, and injecting one (`saveSnapshotsAsEXR`, a string present in the RS binary) gets STRIPPED at startup — the loader round-trips only its known key set. No plist/QSettings store either. Must be re-ticked per RenderView session; no automation lever exists.
- **C4D docked panel does not auto-shrink**: When tab content gets smaller (e.g., switching from QC → Versions), the panel window stays at its taller size. This is a confirmed C4D 2026 framework limitation (no `SetSize`/`ResizeWindow`/`FitToContent` API for docked panels — Maxon staff confirmed). Even Maxon's own panels (Take Manager, AOV Manager) have this behavior. The user must drag-resize manually if they want compact mode. Our `BFV_SCALEFIT` spacers absorb the gap correctly within the layout, but the window frame itself stays put.
- **No native tooltips on widgets**: `BFM_GETCURSORINFO` is not routed to embedded `GeUserArea` in C4D 2026 Python. Section titles include hints (e.g., "click any row...") instead of hover tooltips.
- **C4D 2026 deprecated plugin types**: `c4d.plugins.SceneHookData` and `RegisterSceneHookPlugin` were removed/migrated in C4D 2026 (verified empirically — local 2026 SDK clone has zero references). Sentinel uses `ObjectData.Draw` in `DRAWPASS_OBJECT` for the v1.5.6 Safe-Area Overlay (a scene-root marker, no camera needed) and `TagData.Draw` for the v1.8.0 Sentinel Frame per-camera tag — both confirmed working.
- **CORRECTION (v1.8.0): `TagData.Draw` DOES fire in C4D 2026.** The v1.5.6 note that "`TagData.Draw` is never invoked" was WRONG — the root cause was a missing registration flag, not a removed API. `TagData.Draw` fires reliably when the tag is registered with `info = c4d.TAG_VISIBLE | c4d.TAG_EXPRESSION | c4d.TAG_IMPLEMENTS_DRAW_FUNCTION` (the flag `TAG_IMPLEMENTS_DRAW_FUNCTION` = 256 is REQUIRED; verified live in C4D 2026.301, and confirmed against the working C4DMultiFrame prototype + Maxon staff on developers.maxon.net/forum/topic/12708). Draw signature `Draw(self, tag, op, bd, bh) -> bool`; gate with `if bd.GetDrawPass() != c4d.DRAWPASS_OBJECT: return True` (else it draws 3–4× per frame), filter viewport with `bd.GetSceneCamera(doc) == op`, and treat the draw thread as READ-ONLY (the tag/node come from a CLONED document — Python attributes set via `setattr` do NOT survive the clone; per-node state Draw reads must live in the BaseContainer/params). So an always-on drawer on a camera can be a plain TagData; the ObjectData-marker workaround is only needed for scene-root drawing with no host object.

- **v1.34.1** (Jul 2026): **Fix — las aceptaciones del baseline de QC no sobrevivían a reabrir la escena** (bug vivo desde v1.6.0, encontrado de rebote investigando la identidad de objetos para la fase de checkpoints). **Causa raíz medida**: C4D **regenera el GUID de un objeto en cada carga del documento** — dos generaciones guardadas del mismo archivo dan `GetGUID()` distinto **y** `FindUniqueID(MAXON_CREATOR_ID)` distinto para el mismo objeto.
